# Results v4

## Purpose

`results_v4/` is a clean benchmark rerun after benchmark-code changes made after
v3. It keeps v3 intact and prevents old checkpoints from being mixed with new
method definitions or post-processing outputs.

Run command:

```bash
python3 scripts/run_benchmark.py \
  --models hgb logreg rf et gb ada gnb \
  --probability-calibrations none sigmoid isotonic \
  --output-dir results_v4 \
  --jobs 4 \
  --no-resume
```

`--no-resume` matters: v4 starts from fresh checkpoints, so every cell uses the
same current implementation. v3 remains prior comparison data; v4 is not an
incremental continuation of v3.

## Benchmark design

| Setting | Value |
|---|---|
| Datasets | 15 OpenML imbalanced binary datasets |
| Models | HGB, LogReg, RF, ExtraTrees, GB, AdaBoost, GNB |
| Probability calibration | None, sigmoid, isotonic |
| Seeds | 7, 19, 31, 42, 101, 202, 303, 404, 505, 606 |
| Target error | `alpha=0.10` (90% target coverage) |
| Costs | `C_FP=1`, `C_FN=10` |
| Review capacity | 10% |
| Deferral costs | 0, 0.5, 1, 2 |
| Frontier | 23 alpha values, 0.01–0.45 |
| Bootstrap | 1,000 samples, seed 0 |
| Parallelism | 4 workers |

Expected cells: `15 × 7 × 3 × 10 = 3,150`.

## Methods per cell

| Group | Methods |
|---|---|
| Point baselines | `cost_tuned_threshold`, `class_weighted_threshold`, `random_oversampling_threshold`, `smote_threshold` |
| Conformal | `marginal_cp`, `mondrian_cp`, `aps_cp`, `raps_cp` |
| Rejectors | `confidence_rejector`, `risk_controlled_rejector`, `class_conditional_rejector` |
| Capacity-limited | Capacity-limited confidence, risk-controlled, class-conditional, APS, RAPS, and Mondrian variants |
| Proposed | `cost_controlled_mondrian` |

Each cell uses separate train, probability-calibration, conformal-calibration,
and test roles. Alpha/cost tuning does not reuse final conformal test data.

## What changed after v3

- Added/retained random-oversampling and SMOTE baselines in the current runner.
- Added post-processing outputs: cross-dataset tests, breakeven thresholds,
  noisy-human-review analysis, and review-budget-constrained summaries.
- Added deferral-cost monotonicity validation.
- Updated parallel execution for macOS threading behavior.
- Kept dataset profiles, package versions, Python version, and git commit in
  `run_manifest.json` for reproducibility.

## Why v4 needed after v3

v3 captured the oversampling baseline rerun. v4 captures the later runner state,
including added analyses and execution fixes. Reusing v3 checkpoints would mix
results generated by different code paths and could omit newly computed fields.
Fresh v4 checkpoints make comparisons internally consistent and auditable.

## Files

- `checkpoints/*.pkl`: one result per dataset × seed × model × calibration cell.
- `run_manifest.json`: CLI arguments, dataset profiles, versions, platform, and
  source git commit.
- CSV summaries and figures: written after all checkpoints finish.

Completion check:

```bash
find results_v4/checkpoints -name '*.pkl' | wc -l
```

Expected final count: `3150`.
